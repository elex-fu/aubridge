## 对照基线

- 产品设计 §8.1 已要求 Anthropic unified 429 按实际触发的 5h/7d 窗口休息。当前 `crates/gateway/src/upstream.rs:1305` 只识别 Codex 和通用 reset；`:1665` 的 Anthropic 成功采样固定取 5h reset，未给 429 提供耗尽证据。
- magpie `8abdf53a881facd421b0477647a7cc81beb78bff`，`internal/provider/claude_limits.go:18`、`:60` 保留各窗口种类、模型、利用率和 reset，说明不同窗口不能以另一窗口的 reset 代替。
- sub2api `a3eb7ef302961cba716dc78b39b93b60c467db0e`，`backend/internal/service/ratelimit_service.go:1652`、`:1706` 依据 surpassed-threshold=true 或 utilization>=1 判断 5h/7d 耗尽并选择对应 reset。本轮不采纳其未明确耗尽时猜较早 reset 的分支，双耗尽取有效 reset 的较晚值，避免尚未恢复就试源。

## 任务 01 给 429 分类传入明确窗口证据

状态 `PASS`

- 仅修改 gateway 上游分类及其针对性测试。对 Anthropic 协议 HTTP 429，检查 5h/7d 的 status=rejected、surpassed-threshold=true 或有限数值 utilization>=1。只有明确耗尽窗口才能贡献窗口 reset；双耗尽取两者有效 reset 的最大值。reset 使用 Unix 秒，必须未来且不超过现有 32 天有效期；缺失或非法 reset 不取消耗尽事实，也不借用未耗尽窗口的 reset。
- 明确耗尽映射现有 window_exhausted 和账号 quota 分类；reset 缺失沿用通用 x-ratelimit-reset、Retry-After、900 秒兜底优先级。没有明确耗尽证据时，单纯窗口 reset 不触发 quota 或长期冷却，现有 Retry-After、模型 scope 保持。非 Anthropic 和非 429 不受这条分类影响。
- 成功响应利用率采样维持现有行为，本轮不新增成功响应停源，不引入 aggregate/representative claim、模型专属 7d_oi 或新的持久化字段。未知窗口不能推成账号耗尽。
- Rust 定向覆盖 5h 耗尽与未耗尽 7d 更晚、7d 耗尽与未耗尽 5h 更早、双耗尽、无耗尽仅 reset、NaN/Infinity/坏 reset、耗尽但 reset 缺失、通用 Retry-After 和模型 scope 回归。优先在既有 v1_release 集成测试中核对状态与实际下一次选择。
- 真实 Claude Code 本机回放：两个本机来源，同组首源返回结构化 429 和 5h 耗尽 reset=当前+短周期、7d 未耗尽 reset=当前+7天，备用源成功返回。确认当次切备用、冷却期间仍备用、越过 5h reset 后首源恢复，状态没有采用 7d reset。另回放只有未来 reset、utilization<1、Retry-After=短周期，确认仍走普通短期限规则。禁止外网和真实凭据，所有上游调用从本机日志核验。真实 CLI 通过只证明本机协议/路由回放，不能写为真实厂商限流验证。
