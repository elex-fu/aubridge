## 任务 01 Chat Completions 入站

状态 `PASS`

- 实现 `POST /v1/chat/completions`。解析请求的模型、工具和工具结果供现有候选规划与护栏复用。原生 Chat 上游保留同协议请求选项和响应字段。跨协议请求映射文字、指令、函数工具及结果，兼容可等价映射的常见选项，原生专有字段只发给相同协议。Responses 继续作为现有上游方言。
- 复用候选循环、首段缓冲、工具循环护栏和请求结算。按入站协议输出 SSE 或 JSON。Chat 默认非流式，流式的工具 ID、参数增量、完成原因、终止标记和请求声明的 usage 行保持一致。客户端收到第一段有效内容后按当前流结算。
- 变更落在 `gateway` 的入口、转发和 SSE 投影以及 `translate` 的请求适配。原有 Messages、count_tokens、凭据隔离和路由规则延续。
- 验收 Chat 原生和 Anthropic 兜底的双向工具调用、默认非流式、流式 usage、鉴权、上游空流切换和已输出后的断流。真实 OpenCode 跑一轮文件读取和最终回答，账本显示实际源和 token。

## 任务 02 请求级等待和错误

状态 `PASS`

- 在现有最多四次尝试和每次 30 秒的基础上，增加首段总等待上限 60 秒。免费优先有订阅候选时为其保留末段 15 秒。非流式在应答完成前受该总预算约束。
- 对明确的请求错误和上下文超限直接返回入站协议的结构化错误。可归因于具体模型、厂商兼容性或上游故障的失败继续交给原路由。客户端错误信息来自网关固定文案。
- 验收已知上下文错误保留可识别的 Chat 错误码、校验失败仅问一次、模型形状不兼容仍可换源，并验证总时限与订阅保留时间。回归 Messages 和既有 429/冷却语义。
