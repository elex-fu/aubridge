## 任务 01 展示 Key 来源并使清除操作符合实际作用

状态 `PASS`

- 在现有受 admin 保护的 Provider 行添加可选线协议字段 `key_source`，值为 `saved | environment | none`。前端类型允许字段缺失，旧响应继续使用既有状态展示；字段未知时不推断来源或提供来源专属清除动作。原 `key_set`、`ready` 等布尔字段与权限边界保持兼容。
- Key 取值及来源由同一解析逻辑产生，保留缓存优先、环境变量次之的原顺序，环境变量命名与每次读取行为不变。`saved` 表示现有已保存 Key 缓存命中，不额外宣称持久化后端健康。空白值的存在性和实际可用性保持原口径，不在本轮修改凭据有效性规则。
- UI 在适用的 Key 管理行显示“已保存 Key”或“环境变量 Key”，仅确认来源为 saved 时显示“清除已保存 Key”。环境来源说明来自启动进程的 `KEY_*` 环境变量，需要修改启动环境并重启；不声称识别 `.env` 文件。清除 saved 前后的说明明确：若启动环境另有 Key，清除后会继续使用该环境 Key。操作后重新获取来源。
- 来源是静态配置说明，不表示凭据有效、配额可用或请求必然成功。[route_plan.rs:418](../../crates/gateway/src/route_plan.rs#L418) 的 OAuth 优先、空白 Key 过滤及本机免 Key 规则保持不变；OAuth 和本机来源继续使用现有 readiness 展示，不能由 `key_source=none` 推断它们的认证状态。不给 OAuth 显示无关的环境 Key 来源标签。
- 只添加安全来源枚举，不返回凭据、前后缀、长度、hash、文件路径或环境变量值；不新增日志中的凭据内容，不修改实际凭据和 lookup 策略。本轮仅处理 Key 来源，范围不包含 OpenCode 元数据行为。
