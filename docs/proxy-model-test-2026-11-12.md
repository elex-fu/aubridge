# 代理页模型真实调用测试 · 2026-11-12

状态：已实现；功能、本机回放、最终 358 项回归，以及隔离实例和正常桌面进程的真实调用通过。用户解锁后修复版应用已启动，CUA 在模型选择时丢失窗口，随后系统再次锁屏，原生按钮复核尚未完成。完整命令、首次失败、Codex 修复及真实结果见 [验收记录](proxy-model-test-acceptance-2026-11-12.md)。此文档为产品设计 §6 与 UI 设计 §6.4 的窄范围补充，不改变 0097 BLOCKED 或累计 4 / 10 状态。

## 1. 本次交付

在代理页手动选择对外模型（自动、命名分组、具体模型），通过本机生产推理入口发起一条短文本请求，回答“这个模型名这次是否调用成功、实际由谁回答”。不以目录、路由预览或 Provider 直连检测代替真实代理调用。

沿用现有候选筛选、free-first 或该分组既有规则、凭据、冷却、换源、用量结算；测试本身不保存或改写模型规则、Agent 接线和 Provider 配置。不增加协议/工具矩阵、benchmark、批量测试、自动重试按钮循环、后台定时检测或新依赖。

## 2. 位置与小窗布局

- 代理状态行之后、历史请求之前增加默认收起的 `details.panel`：“测试模型”。置于“手动接入与管理令牌”之前；独立于管理令牌区域，不需要先显示或复制令牌。
- 收起态只有一行标题；本页存在结果时可追加“上次成功 / 上次失败 / 已取消等待 / 未确认”。默认不展开，保持 800×480、最小 760×480 首屏能看见历史入口；不修改窗口尺寸。
- 展开第一行：有可见 label 的“对外模型”下拉（占剩余宽度）＋次按钮“刷新目录”＋主按钮“开始测试”。第二行固定提示：“会通过当前代理发送一条真实请求，可能消耗免费额度或订阅用量。”
- 展示只读测试内容“只回复 OK。”，不加文本编辑器、系统提示、工具、温度或高级参数。提示词固定便于解释与复测，不要求模型必须逐字回复 OK 才算成功。
- 使用已有暖白/青墨样式和 30px 控件。长模型名不挤走按钮；控件容器 `min-width:0`，760px 下必要时动作换至下一行。结果文本与错误可换行，回复最多显示 240 个字符，长内容不撑出全局横滚。
- 展开/收起不触发推理。进行中 summary 显示“测试中”；收起仅隐藏详情，不取消请求。页内“取消测试”始终在展开区可见且可键盘操作，结果通过 `aria-live=polite` 宣告。

## 3. 目录与请求

- 默认选择内置 `aubridge`，显示“自动（免费优先）”；真实请求保留原始模型 ID。目录去重、自动置首，其余维持现有目录的稳定顺序，不能按猜测将名称改成另一个模型。
- 目录使用相同推理身份调用现有 `GET /v1/models`，读取 `data[].id`（与现有 `state.models()` 相同集合，自动别名＋字面模型＋命名分组）；无需拉取 Provider 上游目录。暂停时仍可读取目录。打开测试区时首次读取；“刷新目录”只重新读取本机目录，不触发推理、不改变路由。
- 初次读取中/失败分别显示“读取模型中…”/具体可恢复错误与重试，测试按钮禁用。刷新失败保留上次列表并注明“目录刷新失败，当前为上次读取结果”；用户仍可显式测试旧目录项，最终以生产路由响应为准。
- 刷新成功保留仍存在的选择；已移除的当前项显示“已不在当前目录”，禁用测试并要求重新选择，不静默切到自动。目录声明只证明该模型名可选，不宣称有凭据、额度或推理能力。
- 通过独立推理 helper 调用实际 endpoint 的 `POST /v1/messages`，`Content-Type: application/json`、`stream:false`、`max_tokens:512`、单条 user 文本“只回复 OK。”。512 为输出上限，不是必须消耗的 token 数，用于给推理型模型留出返回普通文本的空间；不额外暴露预算设置。不加 `anthropic-version` 请求头（当前 CORS 不允许，上游转发已自行补齐）。不调用 `/admin/providers/.../check` 或任何新增 admin 测试 API。
- 独立 helper 仅共用 `gateway_access` 取得本机 endpoint；不得使用自动写管理 token 的 `fetchJson` 发推理，也不得将管理 token 当推理 token。桌面当前本机推理 token 固定为 `aubridge`；使用 `Authorization: Bearer aubridge-ui-test`，账本客户端归属 `ui-test`，进入普通生产鉴权与记账路径，不读取 `.env`、Provider key 或用户 Agent token。
- 保持 `redirect:error`。已有网关暂停则禁用开始按钮并说明“恢复新请求后可测试”，不代用户恢复；发送时状态竞争产生的 503 按真实失败呈现。

## 4. 生命周期

- 一次只允许一个测试。发送后禁用选择、刷新和重复开始，按钮改为“测试中…”，显示“取消测试”。网关暂停按钮继续保留原行为，已进入请求依原合同继续完成。
- 每次测试单独 `AbortController` 与递增 run ID；65 秒总超时（网关总预算 60 秒，再留本机调用与回执余量）覆盖连接、等待与完整响应读取。仅当前 run 可更新结果；取消、超时、卸载均清理 timer 和 controller，迟到响应不得覆盖新结果。
- 手动取消显示中性“已取消等待；上游可能仍在处理，用量以历史为准”。客户端超时显示“等待超过 65 秒，未确认完成；可查看历史或手动重试”，不能写成模型不可用。取消/超时不自动重试。
- 离开代理页、关闭窗口时中止本次 fetch，组件卸载清理；重新打开不恢复旧的成功绿标，不在后台继续前端测试。请求可能已到达网关，上游结束与用量以生产账本为准，不能承诺撤销消耗。
- 改变选择立即清除旧结果；再次开始先清除旧结果。同一选择刷新目录后，旧结果标为“上次结果，未重新测试”。保留请求模型与测试时间快照，始终写“本次成功”，不把一次回执升级为持续健康。
- 完成后保留历史筛选、已加载页数与列表，不自动调用会重置分页的 `load()`；结果区提示“记录归属 ui-test，可在下方历史请求中刷新查看”。现有手动刷新继续按原行为处理当前筛选；历史读取失败不能把有效推理回复改判失败，也不能把写入延迟当作未发生请求。不用“最新一条历史”猜配本次结果。

## 5. 结果与证据边界

成功必须同时满足 HTTP 2xx、有效 Messages 响应对象（`type:"message"`、`role:"assistant"`）、存在至少一个非空普通 text block、明确完成的终态（`end_turn` / `stop_sequence` / `max_tokens`），且没有错误对象。未知或缺失 stop_reason 保留“未确认”，不擅自当作完成。HTTP 200 携带 error、空 body、空文本、仅思考/工具、畸形 JSON 或未完成响应都不显示成功。`max_tokens` 终止且已有文本可显示“本次成功（回复已截断）”；不要求文本等于 OK。

成功展示：状态、请求模型、实际来源（既有 `x-aubridge-provider` 响应头）、响应模型（本次 `body.model`）、客户端从发送到完整读取的总耗时、短回复。请求别名、响应 body 的 model 与网关实际路由模型不可混为一谈；当前不存在 `x-aubridge-model`，不为此次测试新增实际模型头。`body.model` 是上游报告值或转译时候选模型，故标签准确写“响应模型”，缺失显示“未知”；若返回同一个自动/分组别名，附“响应返回别名，实际模型未确认”，不宣称已解析成具体模型。不得从当前目录、单一候选、最后一次历史或用户选择反推实际模型。来源类别若没有本次可靠事实也保持未知。

失败展示：失败/未确认状态、请求模型、耗时、已知 HTTP 状态以及安全的结构化错误码/恢复方向。连接/浏览器传输异常写“无法连接本机代理，请确认网关状态后重试”；无候选、凭据未就绪/拒绝、限流/冷却、暂停按实际错误语义给“检查模型源”或等待重试，保留未知原因。不把客户端取消、超时、目录失败归类为上游模型永久不可用。

不得渲染整个上游原始 body、headers、URL 查询或异常对象堆栈。短回复以 React 普通文本呈现，不注入 HTML。错误详情允许展示当前 Messages 网关返回的结构化 `error.type` / `error.message`（当前代码自行构造，不传递上游 raw body）；兼容其他异常形态时不退回显示整个 body。缺少安全详细原因时显示状态/错误码并引导查看现有路由诊断。

## 6. 账本、数据与最小代码边界

真实测试必须走现有 ledger，客户端身份与日常 Agent 分开，历史中能识别为代理页测试；照常记录请求模型、实际模型、尝试来源、结局、用量和耗时，缺失用量保留未知。测试可能影响既有额度、冷却、亲和与轮转状态，这属于真实请求的正常效果，不另做“无副作用”旁路。

不新增数据库表、测试日志、浏览器持久化、遥测或 prompt/回复内容日志。当前短回复仅驻留本页内存；历史与复制诊断继续仅含本机结构化路由元数据，不追加提示词、回复、凭据或管理令牌。

生产改动优先限于 `Proxy.tsx`、`api.ts` 和少量页面样式。已确认当前浏览器无法读取既有 `x-aubridge-provider`，必须仅补 CORS `Access-Control-Expose-Headers: x-aubridge-provider`；不暴露所有 headers、不新增测试后端、不改认证。测试/模型目录均使用既有生产入口和集合。

## 7. 最小验收

1. 前端编译与现有本机隔离回放验证：选具体模型确实携带该 ID 到生产入口；自动/分组仍经现有路由；非空完整回复成功，200 错误/空回复失败或未确认；实际元数据缺失保持未知。不要把回放通过写成真实上游通过。
2. 验证重复点击锁、取消、65 秒超时、换页清理、迟到回执忽略、选择改变与目录刷新失效语义，以及暂停 503。保留一组针对真实 helper/响应合同的最小测试，不建立新测试框架或矩阵。
3. 800×480 与 760×480 各做紧凑布局检查：默认历史仍可达；展开长模型名、错误和回复不产生全局横滚；键盘可达测试/取消/刷新。
4. 用用户已经配置的一个真实上游，手动选择一个实际对外具体模型，发一条固定短提示，经生产代理核对回复与本次路由事实及账本。不得直连替代、注入新 key、改变规则或公开任何 key。若失败，报告实际首个阻碍；不扩大到所有源/协议/工具。
5. 分别记录设计定稿、编译、隔离回放、小窗 GUI 和单次真实上游证据；不据此推进 0097 BLOCKED 或改变既有通过轮次。

## 8. 已核实技术落点与实现顺序

1. `api.ts`：共享现有 `gateway_access` 的 endpoint，新增专用目录/推理 helper，明确使用 `aubridge-ui-test`，不复用强制管理 token 的 `fetchJson`。只读取约定 Messages 结果与安全响应头，不返回凭据。
2. `security.rs`：在既有允许内置 Origin 的响应上 expose 单一既有 provider 头；继续保留现有 Origin/Host/鉴权限制，不扩允许来源、不暴露全部头。
3. `Proxy.tsx` 与必要样式：落折叠面板、单次请求状态机、取消等待/65秒超时/卸载清理、成功合同与严格未知。请求用量不在新结果卡重复展示，避免 translator 默认 0 被误作真实计费；用户在原历史查看账本报告值。
4. 精确复用已有回放：`integration.rs` 的 group/auto/named-group rewrite；`v1_release.rs` 的 HTTP200 空体/嵌入错误/用量未知案例。新覆盖仅补 ui-test 身份、目录与 provider CORS 可读、前端结果分类和生命周期。本次不声称已有流式断开测试已经证明非流式 AbortController 能取消上游。

默认 800×480、最小 760×480 与紧凑 UI 设计均不改。本补充仅授权该测试能力需要的前端 helper、局部样式和单个 CORS expose 元数据头；没有新后端测试路径。
