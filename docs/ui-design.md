## 1. 定位与目标用户

- UI 是**小白的第一入口**:用户不读 README 也能完成
  "装好 → 有 Provider → Agent 接线 → 跑起来"。
- 开发者回退通道(`.env`、手编配置文件、`group/a+b` 手写语法)
  保留但不出现在 UI 词汇里。
- 页面数固定 6 页,不再增页。
- 主窗口默认 800×480 且不最大化，最小尺寸为 760×480，均为逻辑尺寸。当前改版在两个宽度保持六项导航单行；主区纵向滚动，长表格只在局部容器横向滚动。
- 通用弹层与视口边缘保留 16px 间距，长内容在弹层内部滚动，保存、取消等末尾操作始终可滚动到达。

品牌采用 `brand-design.md` 定义的“线桥”。页头在 aubridge 标题前显示 24×24 的彩色应用图标，favicon 复用同一 `crates/smoke/icons/app-icon.svg`，由 Vite 处理资源路径；不另绘桥形。标题与图标紧凑排列，六页导航在800/760宽保持单行，窗口尺寸、页面滚动与弹层滚动沿用上述约束。程序坞、桌面和托盘的资产与原生展示证据按品牌文档分别验收。

## 2. 竞品结论(cc-switch / magpie 分析)

| 来源 | 借鉴 | 拒绝 |
|---|---|---|
| cc-switch | 预设即卡片、粘贴 key 即完成;主操作按钮固定不随滚动消失;状态图标一屏可判 | 视图无节制膨胀(14 个 view) → aubridge 守死 6 页 |
| magpie | 组"一键拥有"的零配置思想;决策流可视化 | 意图路由/嵌套组/自定义规则 = 配置爆炸 → 路由规则只给固定枚举,只选择不配置 |

小白断点(现状,本方案要消灭的):

1. key 输入要懂 `.env` + `KEY_<ID>` 命名 + 重启进程;
2. 模型选择要手编 agent 配置文件、会写组语法;
3. 首启打开是数据表,没有"从这开始";
4. 动作(接线/配模型)与结果(请求去哪了)脱节。

## 3. 设计原则

1. **Provider 是用户心智主体**:用户"添加一个源",不"管理密钥"。
   密钥只是 Provider 行内的一个状态字段。
2. **组在"模型"页可视化,规则只选不配**:路由规则是固定枚举,
   默认值写死,拒绝规则编辑器。
3. **状态驱动引导,不新增引导页**:引导卡只在缺什么时出现,
   就绪后消失。
4. **动作↔结果闭环**:失败/无候选的请求行带跳转链接,指回
   Provider 页。
5. **UI 不泄漏敏感值**:provider key 只回"已设置/未设置"布尔,
   admin token 可复制但永不入日志/分享卡(§7 红线)。
6. **Agents 页一屏放完**:汇总压缩为卡片行,不出现滚动才能
   看全的表。

## 5. 信息架构(6 页;设置页独立为最右页签,2026-11-06 用户拍板,
   此前曾暂驻 Provider 页底部)

```
导航:Agents | Provider | 模型 | 代理 | Plugin | 设置

Agents   动作面+观察面:顶部汇总,下部生效 agent 清单(一屏)
Provider 源管理:api key + 模型 + 可反代 agent,支持添加
模型     分组管理:同模型多源映射 / 跨模型合并,规则只选

设置     凭据回写(高级):共享登录开关 + stash 备份/一键还原
```

## 6. 页面设计

### 6.1 Agents 页(仪表盘并入,一屏约束)

```
┌ 汇总区(压缩为卡片行,不再整表) ───────────────────────────┐
│ [本月省 $X·分享卡] [源健康 5/6 正常] [今日请求 128·成功率 96%] │
└────────────────────────────────────────────────────────────┘
┌ 生效的 Agents(自动检测已安装,缺的显示安装提示) ──────────┐
│ Claude Code   [已接线 ✓]  用 [▼ 自动(aubridge)]  [编辑] [测试] [断开] │
│ Codex         [接线 →]    用 [▼ 自动(aubridge)]  [编辑] [接线] │
│ OpenCode      [未安装 — 安装提示]                             │
│ [+ 添加 Agent](手动登记未检测到的 agent/自定义接线)          │
└────────────────────────────────────────────────────────────┘
```

- 汇总区包含分享卡、源健康和最近请求。成功来源按最近请求中实际选中的历史尝试计数，分为免费档、订阅和来源未知。请求明细见代理页「历史请求」。
- Agent 行:接线状态 + 使用模型(下拉)+ 启用方式(接线/断开)。
- **[编辑]** 弹层 = 单 agent 的高级配置:
  - Claude Code:快捷选择已有模型后同步 `model`、`ANTHROPIC_MODEL`
    与已存在的角色映射;Sonnet / Opus / Haiku / Fable 四个角色可填
    显示名称、实际请求模型和 1M 声明(写成模型名 `[1M]` 后缀);
    可编辑兜底模型、子 Agent 模型、权限模式、输出/上下文/思考
    token 上限、自定义请求头和常用开关;另提供完整
    `settings.json` JSON 编辑。密钥读取显示 `••••••••`,保存时
    未改动的占位符回填原值。
  - Codex:只编辑受管 `aubridge.config.toml` 顶层字段(模型、推理
    强度/摘要、输出详细度、审批策略、沙箱、Web 搜索、上下文和输出
    上限);接入地址与回环凭据由 aubridge 独占。未接线时不可编辑。
  - 两端保存都带读取时的 revision;文件被外部修改时拒绝覆盖并提示
    重新加载。OpenCode 仍使用原简单模型弹层。
- **[测试]** 弹层页执行后端固定的真实 CLI 命令并展示 stdout /
  stderr / 耗时 / 退出码,命令本身不可由前端拼接。Claude Code 使用
  `claude -p --strict-mcp-config --no-session-persistence`;Codex 使用
  `codex --profile aubridge exec --skip-git-repo-check --ephemeral
  --sandbox read-only`。测试在临时目录运行、150 秒超时、输出脱敏,
  可能消耗订阅额度,页面明示。
- Codex CLI 接线后显示 `codex --profile aubridge`。编辑只更新该 profile 的模型与顶层高级字段。
- OpenCode 在已接线且配置受管时可编辑默认模型。尚未显式选择时显示「沿用 OpenCode 原默认」；保存后使用所选默认，正常断开时恢复原值。目录同步继续保留默认选择。
- 全部源就绪前,汇总区显示引导卡(§7)。

### 6.2 Provider 页

```
┌ Provider ────────────────────────────────────────────────┐
│ 智谱 GLM 免费档   模型: glm-4.5-flash, glm-4.6v-flash        │
│   api key [●已设置] [设置] [清除]   服务 Agents: 2 个已接线    │
│ ModelScope 免费档 模型: Qwen/…, zai-org/GLM-4.5-Flash        │
│   api key [○未设置] [设置]       服务 Agents: 0                │
│ [+ 添加 Provider](预设列表选一个 → 粘贴 base URL/key)         │
├ 可反代的 Agents(当前已安装且支持接线) ──────────────────────┤
│ Claude Code · Codex · OpenCode(自动识别;检测不到的不出现)   │
└────────────────────────────────────────────────────────────┘
```

- 行主体:名称、类别(订阅/免费档)、模型列表、api key 布尔、
  正在服务多少个已接线 agent(闭环:改这里能预见影响面)。
- [设置] = 弹层粘贴 → 保存 → 只回布尔回执,网关凭据缓存即时
  失效,**无需重启**;取 key 顺序:keyring → `KEY_<ID>` 环境变量
  → 占位 401。
- Key 状态区分已保存和环境变量来源。清除已保存 Key 后，网关会继续使用可用的环境 Key。
- [+ 添加 Provider]:预设(内置 registry presets)选一个 →
  base URL + key → 保存。自定义 provider = cc-switch 式预设
  卡片流,字段固定(base/kind/models/key),无自由 JSON 编辑器。
  新增自定义源必须明确选择「官方免费档」或「自有订阅（Coding Plan等）」，初始不预选。免费档可用于仅免费档分组；自有订阅作为订阅源参与路由。
- 自定义源可编辑类别、模型清单和上游路径。路径修改要求协议、主机及有效端口相同。原有 Key 和历史继续沿用，保存后更新路由、模型发现和仍受管的 OpenCode 配置。
  已保存的自定义 Chat 源可读取来源模型目录，搜索并选择模型加入草稿，显式保存后生效。已有模型顺序保留；目录不代表免费额度、工具能力或推理可用性。地址草稿变更后须先保存再读取。
- "可反代的 Agents"区只读,与 Agents 页同一检测数据源。
- 「检测连接」向所选源和模型发送一条短请求，多模型源默认选中首个模型。显示成功、鉴权失败
  或上游限额等状态。自定义源可选择 Chat Completions 或 Anthropic Messages。
  成功编辑连接、保存或清除 Key、删除源后，清除该源的检测结果并忽略迟到回执。暂停或恢复推理时保留当前检测结果。
- OpenRouter key 预算使用美元。免费请求状态逐模型显示候选资格或冷却
  到期时间，无法获知剩余请求数时显示未知。
- 订阅源的路由状态逐模型显示阻塞原因及可重试时刻，摘要显示暂不可用的模型数。Key 就绪与路由状态分别展示；重试时刻是当前快照，不保证届时恢复。
- 「刷新 OpenRouter 免费模型」显示目录更新时间、工具能力和上下文上限。
  刷新失败时显示原因并沿用上次有效目录。目录变更同步到仍受管的 OpenCode 配置，
  也可在 Agents 页手动同步。
- 「从 cc-switch 导入」(勾选即新增,cc-switch-import-design
  §4.4):弹层列出候选行(名称/来源/base/协议/模型数/导入后的源
  ID),skip 行(官方登录、本地代理自环、范围外)灰显带原因、
  不可勾选;提交后逐行报告已导入与失败原因,任何成功都刷新源表。
  key 导入即进钥匙串,值不回显。
- 源行 meta 有窗口读数时显示「用量 5h/7d 已用百分比 · 重置时刻」
  (被动采样与主动查询合并口径);detail 的「额度」section 展开后
  按需拉取窗口历史并画折线(每窗口一条剩余百分比曲线 + 虚线均匀
  消耗参考,单 series,标题即窗口名;无读数显示引导文案)。
  v1 只展示,不驱动路由决策(quota-plan-design D4)。

### 6.3 模型页

```
┌ 对外模型(分组) ──────────────────────────────────────────┐
│ 自动(aubridge)   全部源自动调度            [内置·不可删]     │
│ glm-4.5-flash     同名多源: 智谱, ModelScope                  │
│   规则: [▼ 免费优先]  成员: 2 个 provider                     │
│ my-daily(自定义名) 跨模型合并: glm-4.5-flash + Qwen/…        │
│   规则: [▼ 顺序兜底]  对外名: my-daily  [编辑] [删除]          │
│ [+ 新建分组]                                                 │
└────────────────────────────────────────────────────────────┘
```

- 两类分组,同一张表:
  - **同名多源映射**:同模型名由多个 provider 提供 → 对外仍是该
    模型名,agent 无感,规则选择即可;
  - **跨模型合并**:不同模型组成一组,用户自定义对外名(如
    `my-daily`),agent 只见这个名。
- **路由规则 = 固定枚举,只选择**:
  - 免费优先（默认）。可用免费模型在整个分组内优先于订阅。
  - 仅免费档。只使用标记为免费档的源，并可在组内免费模型间切换。分组列表与编辑器标注仅有订阅源的成员，并提醒缺少免费档成员的分组。
  - 顺序兜底。按成员列表顺序尝试，失败后换下一个候选。
  - 轮流。以成员列表为基础应用现有轮次。
  没有规则编辑器、没有嵌套、没有意图路由(magpie 反面教训)。
- 组存到持久化 store(候选:`~/.aubridge/config.json` 字段级
  合并同路径),网关启动时并入候选表;agent 手编 `group/a+b`
  语法继续兼容(高级通道,UI 不暴露语法拼装过程)。
- 分组数据也给 Agents 页模型下拉复用。
- 编辑器显示已选成员的有序列表，可上下移动。新选成员追加到末尾，保存后生效，取消会丢弃草稿。目录暂不可用的成员仍可移动或移除。
- 已保存分组可按普通文本或工具调用预览候选顺序、类别和跳过原因，默认普通文本。预览只读取本机路由状态。实际顺序还受请求能力、会话和负载影响。
  网关停止时，预览提示当前推理会被拒绝，并保留恢复后的候选快照。

### 6.4 代理页

```
┌ 代理网关 ──────────────────────────────────────────────────┐
│ 状态: [运行中 ●]  [停止]   监听: 127.0.0.1:3427(回环,写死)  │
│ 接入方式:                                                     │
│   Agent 端点   http://127.0.0.1:3427/v1        [复制]        │
│   当次管理令牌  ••••••••              [显示令牌] [复制]        │
│   (每 agent token aubridge-<agent>,在 Agents[编辑]里复制)   │
├ 历史请求(每页 20 条,来自 ledger decisions) ────────────────┤
│ 时间与耗时 | 模型 | agent | 选中源 | 尝试序列 | 结局            │
│ (失败/无候选行 → "去设置 Provider" 链接)                     │
└─────────────────────────────────────────────────────────────┘
```

- 历史请求 = 原仪表盘"最近决策"表整表搬入此处(Agents 页只留
  计数卡片)。
- 管理令牌默认遮挡，可主动显示或复制。重新打开代理页时恢复遮挡。
- 历史请求可手动刷新，按客户端 ID、选中源 ID、选中源类别、结果和模型 ID 筛选，并加载更早的记录。模型 ID 精确匹配请求模型或实际模型。类别以实际选中的尝试为准，旧记录缺少类别时可在“全部”查看。每条记录展示尝试顺序、实际命中以及跳过候选的原因。
- “复制诊断”将单条请求的路由结果、耗时、用量和候选原因写入本机剪贴板。内容限定为结构化元数据。
- 时间列展示首段就绪与请求结算的总耗时，尝试列表同时显示每次尝试的耗时。非流式按完整响应就绪计算首段。
- “清空请求历史”经确认后删除全部已完成请求的明细，用量统计继续累计。
- [停止]/[运行] 控制网关是否接受新请求(进程不退,重新启动应用
  即恢复;停止是软开关,不是退出进程)。
- 托盘可暂停或恢复新推理，已进入的请求继续完成。托盘与代理页同步同一运行状态，状态通知保留历史筛选和分页；同步失败时页面明确提示。
- 「测试模型」可手动选择自动、分组或具体模型，通过真实 `/v1/messages` 生产路由发送固定短文本。目录不代表可用，成功必须有完整非空文本回执；显示请求模型、响应模型、来源与耗时，取消仅停止等待。真实用量提示、65 秒等待、历史隔离与验收边界见 [模型真实调用测试](proxy-model-test-2026-11-12.md)。
- 监听地址写死回环(§6 红线,UI 不提供改监听地址的入口)。

### 6.5 Plugin 页 — 不动

默认全关语义照旧(§9),小白全生命周期可不进此页。

## 7. 首启操作流(状态驱动,无新页面)

```
启动 aubridged → 打开 UI(落在 Agents 页)
  → 引导卡 ①:Provider 页粘贴 api key(保存即生效,无重启)
  → 引导卡 ②:Agents 页接线 agent,模型选"自动"
  → 引导卡消失,Agents 页常驻;请求明细去"代理"页看
  → 出错(无候选/401):历史请求行链接 → 跳回 Provider 页
```

小白全程不需要知道:端口、token、`.env`、`group/a+b` 语法、
配置文件路径。想分模型时进"模型"页点选,不写语法。

## 8. 通道与安全红线落点

| 通道 | 状态 |
